# CLAUDE.md

CCDV-F practice-exam web app — SvelteKit 5 (runes) + libSQL/Turso, deployed on
Vercel. **Read `CONTEXT_MAP.md` before non-trivial work** — it has the full
architecture, design rationale, and a running list of gotchas hit while
building this; this file is just the fast-reference summary.

## Commands

```
pnpm run dev       # vite dev — local dev server
pnpm run build     # vite build — output goes to .svelte-kit/output/
pnpm run preview   # serves the build (what `pnpm run build` produced)
pnpm run check     # svelte-kit sync && svelte-check — run before calling any change done
pnpm run lint      # prettier --check . && eslint .
pnpm run format    # prettier --write .
```

A stray `build/` directory may exist locally from an earlier setup — it is
**not** regenerated by `pnpm run build` (that writes to `.svelte-kit/output/`,
which `pnpm run preview` actually serves) and is safe to ignore/delete.

Question bank rebuild (only needed when editing `data/ccdv-f/*.jsonl`):

```
python scripts/markdownify.py
python scripts/import.py data/ccdv-f --db db/claude-mock-exams.db --schema db/schema.sql
python scripts/rebalance_difficulty.py
```

The live app reads exclusively from Turso Cloud, never the local `.db` file —
a local rebuild does **not** update production; see CONTEXT_MAP.md's
"Known gaps" for the manual sync step.

## Non-negotiable invariants

- **Never let the client derive a mock exam's answer key while the exam is in
  progress.** `QuestionPublic`/`ChoicePublic` (`$lib/types.ts`) structurally
  omit `is_correct`, `reasoning`, and `sort_order` — don't add fields back to
  these types without checking whether they leak correctness (the source
  JSONL always lists the correct choice at `sort_order 0`, so even that field
  alone is a leak). Exam grading (`api/exam/submit`) re-derives correctness
  server-side from the DB; it never trusts a client-supplied answer.
- **No full-question-bank loads.** Every question fetch is a targeted SQL
  query scoped to exactly what's needed (sampled ids, or the ids the client
  says it was shown) — see `$lib/server/queries.ts` / `examSampler.ts`. This
  isn't a style preference, it's load-bearing for Vercel's serverless model.
- **Runes mode everywhere in `src/`** (`vite.config.ts` forces this outside
  `node_modules`). State modules (`$lib/state/*.svelte.ts`) export a single
  `$state` object mutated only through exported functions, persisted to
  localStorage synchronously inside each mutator — never reassign the
  exported state object itself, and don't add a module-level `$effect` (not
  valid outside a component).
- **Before touching `initPracticeSession()`/`initExam()`**: read the
  "effect-loop gotcha" in CONTEXT_MAP.md first. Reading a `$state` field
  right after reassigning it, inside a function called from an `$effect`,
  can create a self-triggering infinite loop — bisect with `git stash` on
  subsets of a change if you hit `effect_update_depth_exceeded` and the
  error itself doesn't point at the cause (it won't).
- **Study Notes content** (`src/lib/notes/content/*.md`) has its own syntax
  contract enforced by a custom renderer — no `#` h1, specific blockquote
  callout labels, `{{term|def}}`/`{{youtube:ID|title}}` syntax, Python-only
  code samples. Full spec is in CONTEXT_MAP.md's "Study Notes" section —
  don't freehand a different convention.
- **Never fabricate a YouTube video id or a doc URL** anywhere in Study
  Notes content. Verify via WebSearch/WebFetch first; omit rather than guess
  if it can't be confirmed. (One invented id already slipped through once
  and had to be caught and removed — see CONTEXT_MAP.md.)

## Verifying UI changes

This is a Windows/PowerShell environment; headless Chromium screenshots
**do not render custom scrollbars or some overlay-style UI** regardless of
CSS correctness — that's a headless-mode default, not a bug. If a visual
check looks wrong only in a headless screenshot, re-verify with
`chromium.launch({ headless: false })` against a local Chrome install before
concluding there's a real issue.

For anything touching `/practice` or `/exam` end to end (not just `/notes`),
starting a session requires the live Turso connection in `.env` — there's no
local-only fixture data path.

## Where things live

See CONTEXT_MAP.md's "Repository layout" for the full tree. Quick pointers:

- Question-bank rendering: `$lib/server/markdown.ts` (sanitized — question
  content flows through admin upload).
- Study Notes rendering: `$lib/server/notesMarkdown.ts` + `notesContent.ts`
  (**not** sanitized — content is static/repo-authored only; caches rendered
  HTML in module scope, don't remove that without reading why first).
- Session/attempt state: `$lib/state/practice.svelte.ts`,
  `exam.svelte.ts`, `history.svelte.ts`, `theme.svelte.ts`.
- Shared choice-answering UI: `$lib/components/ChoicePicker.svelte` (used by
  both practice and exam modes — includes select-N capping and the
  strike-off/eliminate-distractors feature).
